# CRM & Telephony Integration

Система, связывающая CRM и виртуальную АТС в единый рабочий сценарий: заявка из CRM
доходит до выездного менеджера, менеджер звонит клиенту, **не получая его номер телефона**.

Заказная разработка по техническому заданию - [TECHNICAL_SPEC.md](TECHNICAL_SPEC.md).

## Бизнес-задача

В компании с выездными менеджерами клиентская база - главный актив. Передавая менеджеру
номер клиента, компания теряет над ним контроль: контакт остаётся у сотрудника и уходит
вместе с ним при увольнении.

Одновременно нельзя терять скорость: оператор не должен вручную переносить данные между
CRM, мессенджером и телефонией, а менеджер - ждать, пока с ним свяжутся.

Решение: номер клиента не покидает базу. Менеджер видит карточку заявки без телефона,
запрашивает звонок, а соединение устанавливает АТС - сначала дозваниваясь менеджеру,
затем подключая клиента. В мессенджере номер не появляется ни разу.

## Архитектура

```text
   amoCRM                                            Mango Office
      │                                                   ▲
      │ заявка                                            │ callback
      ▼                                                   │
┌──────────────────────────────────────────────────────────────┐
│                        Приложение                            │
│                                                              │
│   aiogram (роли, состояния)      FastAPI (webhooks, health)   │
│              │                            │                  │
│              └────────► services ◄────────┘                  │
│                    order · amocrm · mango                    │
│                            │                                 │
│                     repositories → PostgreSQL                │
└──────────────────────────────────────────────────────────────┘
      │                                              │
      ▼                                              ▼
  оператор                                       менеджер
 (создаёт заявку,                            (получает карточку
  одобряет звонок)                            без номера клиента)
```

Состояние заявки - конечный автомат:

```text
SENT ──► CALL_REQUESTED ──► CALL_APPROVED ──► CALL_IN_PROGRESS ──► COMPLETED
  │            │                  │                   │
  └────────────┴──────────────────┴───────────────────┴──────────► CANCELLED
```

## Технологии

`Python 3.11` · `aiogram 3` · `FastAPI` · `SQLAlchemy 2 (async)` · `asyncpg` ·
`Alembic` · `PostgreSQL 15` · `pydantic-settings` · `Docker`

## Что реализовано

**Интеграция с amoCRM** - авторизация, чтение заявок, работа с пользовательскими полями,
хранение токенов в базе с обновлением. Предусмотрен режим-заглушка: система разворачивается
и тестируется без доступа к боевой CRM.

**Интеграция с телефонией** - инициация звонка через callback-API Mango Office с подстановкой
служебной линии, приём вебхуков о состоянии вызова, журнал всех соединений.

**Ролевая модель** - администратор, оператор, менеджер. Права проверяются на каждое действие,
а не только при входе в раздел.

**Рабочие группы вместо регионов** - в группе в любой момент один активный менеджер, заявка
уходит адресно. Это убрало конкуренцию за заявку и состояние «взял, но не поехал».

**Конечный автомат заявки** - переход в следующий статус возможен только из разрешённого
предыдущего. Кнопка «Позвонить» действительна один раз и только после одобрения.

**Развёртывание** - Docker с автоприменением миграций при старте контейнера.

## Инженерные решения

**Номер клиента изолирован.** Телефон не попадает ни в сообщения, ни в `callback_data`,
ни в логи - хранится только в базе и извлекается в момент инициации вызова. Это требование
определило структуру всей передачи данных: наружу уходят идентификаторы, не значения.

**Звонок без интернета у менеджера.** Выездной сотрудник может оказаться без связи. Тогда
он набирает служебную линию, а система соединяет его с клиентом - сценарий работает
на обычном голосовом канале.

**Автозакрытие зависших заявок.** Заявка, застрявшая в промежуточном статусе, закрывается
автоматически - иначе очередь менеджера забивается тем, что уже неактуально.

**Определение сотрудника без username.** В Telegram у пользователя может не быть username,
а числовой ID он обычно не знает. Регистрация сделана тремя путями: по контакту, по пересылке
сообщения и по username - если бот уже видел этого пользователя.

## Запуск

```bash
git clone https://github.com/Timmn3/crm-telephony-integration.git
cd crm-telephony-integration
cp .env.example .env      # заполнить своими значениями
docker compose up -d
```

Без Docker:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
alembic upgrade head
python3 -m app.main
```

## Тесты

```bash
pip install -r requirements-dev.txt
pytest -q
```

Покрыты интеграции с CRM и телефонией, логика заявок, репозитории, разбор телефонных
номеров и маршрут звонка.
